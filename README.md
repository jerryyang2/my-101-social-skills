# 我的101堂社交技巧課

以特教教師備課與課堂操作需求為起點，將社交情境故事、技巧步驟、角色演練、互動遊戲及學習單整合在同一套網頁平台。教師可以依學生的理解、溝通、感官與情緒需要選擇活動，再觀察學生在實際情境中需要哪些支持。

線上展示：[開啟我的101堂社交技巧課](https://jerryyang2.github.io/my-101-social-skills/)

本專題採 **AI 協作開發**，重點在於把教學需求轉成可操作的介面，持續核對課程與畫面的對應，並處理教材在不同輸出版本間的一致性。現有成果展示的是功能與內容整合，尚未完成可證明教學成效的研究。

## 專題起點與使用者

特教教師經常需要在故事、提示卡、簡報、學習單與親師溝通文字之間切換。素材分散時，同一堂課的內容容易不一致，上課操作也會被找檔案或切換視窗打斷。本專題希望把這些流程連起來，讓教師能從選課一路進入投影、演練與課後練習。

主要使用者是國小特教與融合教育情境中的教師。學生在教師引導下參與故事討論與情境活動；平台提供調整與支持工具，教材是否適合個別學生，仍須由教師判斷。

## 設計與實作中學到的事

### 畫面更新需要統一的狀態來源

課堂的遊戲分頁會依目前課程重新建立內容。如果只把新介面附加到舊容器，連續切換就可能留下重複畫面。目前 `switchGameTab()` 先更新 `currentGameTab`，再交由 `renderSlide()` 清空主內容並重新渲染，讓更新流程集中在同一個入口。

可以閱讀 [classroom.js](備課平台/classroom.js) 的 `switchGameTab()`、`renderSlide()` 與 `renderSlideGame()`。檢查時不能只點一次按鈕，而要連續切換兩種遊戲、切換課程，再返回原本課程，確認內容與按鈕數量都正確。

### 工具能打開還不夠，內容也要屬於目前課程

同一套教師工具會從備課頁或課堂投影開啟。兩個頁面的選課狀態若沒有對齊，工具即使正常顯示，也可能帶入另一堂課的草稿。目前 `getCurrentLessonBriefing()` 優先使用投影中的 `currentBriefing`，再讀取備課頁的選課入口。

對應程式在 [teacher-tools.js](備課平台/teacher-tools.js)。這個案例讓我開始注意資料的取得順序，以及共用工具如何確認呼叫端的課程狀態。

### 多種教材輸出需要可重複的檢查

同一堂課同時出現在備課、投影片、學習單與電子書裡。修改一個故事或選項時，不能只檢查眼前的頁面；也要確認中文出版教材、英文輸出與目錄連結是否同步。

英文版由中文來源與本地翻譯對照檔編譯，訪客操作網站時不呼叫翻譯服務。`build-manifest.json` 記錄來源、建置輸入與輸出的 SHA-256，驗證程式用它檢查是否過期。這能發現版本不一致，教材語意與教學適切性仍需要人工審閱。

相關流程見 [雙語維護說明](localization/README.md)、[verify_build.py](localization/verify_build.py) 與 [verify_all_tocs.py](scripts/verify_all_tocs.py)。

## 技術架構

網站主要使用 HTML、CSS 與原生 JavaScript，課程以穩定的課程 ID 連結各個頁面及資料集。前端不需要先打包，使用靜態 HTTP 伺服器即可啟動。

```text
課程與情境資料
  app.js / roleplay-data.js / worksheets-data.js
                 │
                 ├── 備課與教師工具
                 ├── 課堂投影與互動活動
                 └── 學習單與五冊電子書

中文網站 + 翻譯對照檔
                 └── Python / Node.js 建置與檢查 ── en/ 英文網站

瀏覽器設定與進度
                 └── localStorage；同源分頁以 storage 事件更新
```

| 技術 | 在本專題中的用途 |
| --- | --- |
| HTML、CSS、JavaScript | 網頁、教材呈現、課堂互動與狀態處理 |
| Three.js | 3D 場景、角色與群島移動；使用既有引擎進行整合 |
| Web Speech API 與隨站音檔 | 朗讀與語音支援；實際語音能力依瀏覽器與裝置而異 |
| localStorage | 記住語言、星星、自訂課程及相關本機設定 |
| Python、Node.js、Acorn | 電子書產製、翻譯建置、JavaScript 解析與驗證 |
| Git 與 GitHub Actions | 版本管理，以及 GitHub Actions 的 Pages 驗證與部署 |

## 本機啟動

需要 Python 3。於專案根目錄執行：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

以瀏覽器開啟 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)。停止伺服器時，在終端機按 `Ctrl+C`。日常瀏覽不需要安裝 Node.js 套件；執行下列建置與檢查時才需要 Node.js 與 npm。

### 建議的短程展示

1. 從首頁進入備課平台，選一堂課，指出故事、三步驟技巧與教學建議如何對應。
2. 開啟同一堂課的投影，走過故事、技巧與角色劇場，再連續切換遊戲分頁。
3. 開啟教師工具與學習單，確認標題及草稿仍屬於同一堂課。
4. 切換英文，確認課程與投影片位置保留，再展示一本線上電子書的目錄跳轉。

展示請使用虛構資料。這套流程展示的是功能與狀態一致性，不用星星或遊戲分數推論學生是否已精熟。

## 可以重現的驗證

在專案根目錄執行：

```bash
npm ci --prefix localization --ignore-scripts
python3 localization/verify_build.py
node localization/verify_english.cjs
node tests/island-paths.cjs
```

| 檢查 | 涵蓋範圍 |
| --- | --- |
| `verify_build.py` | 來源與輸出雜湊、英文頁面連結與章節、favicon、頁內 JavaScript 及靜態英文文字 |
| `verify_english.cjs` | 英文 JavaScript 語法、三套 101 課資料的結構與不應改變的欄位、語言切換與儲存失效備援 |
| `island-paths.cjs` | 群島路徑是否位於可行走區域、移動中斷與抵達、角色高度及任務入口 |

五冊中文 PDF 及網站使用手冊保留在本機，不放入公開儲存庫。維護端另以 `scripts/verify_all_tocs.py` 核對五冊 PDF 的頁數、各冊 101 個目錄連結與 HTML 錨點；這項檢查需要本機 PDF 及 `pypdf`，僅下載公開原始碼不能直接重現完整的 PDF 驗收。

自動檢查通過不代表所有功能與裝置都沒有問題；朗讀、連續操作、投影畫面、列印版面及教材內容仍須實際檢查。

## AI 協作與我的角色

這個專題有很大一部分程式由 Codex 等 AI 工具協助實作與修改。我的角色是與教學使用者討論情境、整理需求、提出修改條件、操作結果並追查問題，再逐步理解程式；教材適切性的判斷需要教師的專業參與。

AI 參與程式草擬、除錯建議、翻譯與文件整理。我不把「能讓 AI 做出功能」等同於「已能獨立實作全部模組」，也不把第三方引擎、教材參考與 AI 產出都算成個人原創。現階段值得繼續深化的是：用自己的話解釋狀態流程、判斷錯誤原因，並練習獨立重作小範圍功能。

## 限制與下一步

- **資料保存**：目前星星、進度與自訂資料保存在同一瀏覽器的 localStorage。沒有自動跨裝置同步、帳號權限或可靠備份；群島另提供手動接關碼。更換網站網域不會自動帶走原有紀錄。保留的 Netlify Function 原型不屬於目前前端的必要服務，不能視為已完成的安全多人後端。
- **教學驗證**：尚未完成系統性的使用者研究或學習成效評估。後續可先選一個明確任務，觀察教師找到教材所需的步驟、錯誤操作與回饋，再設計合適的學習觀察指標。
- **程式維護**：`app.js` 仍混合大量教材與介面邏輯；下一步是釐清資料 schema 與狀態邊界，針對切課與共用工具補足回歸驗證。
- **個別需求與翻譯**：有語音、視覺支持與可調工具，不代表適用所有學生或已通過完整無障礙檢驗；英文長篇教材也仍需要專業語言審訂。
